<section class="preamble">
<p>This file is a 3md document that teaches 3md. Scrub the Z axis to read it in order. The &quot;anatomy&quot; plane contains a fenced code block with a literal @plane line inside it, which the parser treats as body text, not a new plane.</p>
</section>
<section id="plane-z-0" data-z="0" aria-label="what">
<h2>what</h2>
<h1>What is 3md</h1>
<p>Markdown with a Z axis. A document is ordinary Markdown sliced into planes along one axis you name yourself: time, frame, layer, depth, space, anything.</p>
</section>
<section id="plane-z-1" data-z="1" aria-label="anatomy">
<h2>anatomy</h2>
<h1>Anatomy</h1>
<p>A required frontmatter block declares the version (the magic marker) and the axis. Each <code>@plane</code> directive starts a plane; the Markdown between directives is that plane&#39;s body. Here is a whole 3md file shown inside a code block:</p>
<pre><code>---
3md: 1.0
axis: time
title: My Week
---
@plane z=0 label=&quot;Monday&quot;
# Monday
- [ ] Standup</code></pre>
<p>The <code>@plane</code> line above sits inside a code fence, so this document still has four planes, not five.</p>
</section>
<section id="plane-z-2" data-z="2" aria-label="axis">
<h2>axis</h2>
<h1>The axis is yours</h1>
<p>The <code>axis:</code> value is free-form metadata. The same parser serves a planner (time), an animation (frame), an annotated contract (layer), and a scene (space). Tools decide how to lay the planes out.</p>
</section>
<section id="plane-z-3" data-z="3" aria-label="tooling">
<h2>tooling</h2>
<h1>Tooling</h1>
<p>Parse it in Swift (ThreeMD) or TypeScript (@corvidlabs/threemd), validate and render it with the <code>threemd</code> CLI, and trust that both parsers agree, thanks to the shared conformance suite.</p>
</section>
</main>
