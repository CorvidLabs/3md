# Context

Godot games need a native reader and writer. The addon lives in `gdscript/` and is copied into a game as `addons/threemd`. It is not a fifth package registry publish.

## Decisions

- Godot 4.7 is the development engine (`/opt/homebrew/bin/godot`, 4.7.2). The project feature tag is `4.7`.
- GDScript has no exceptions. Public calls return a `ThreeMDDocument` or a `ThreeMDError`. Storage, composition, and editing use the same error codes as TypeScript.
- Coordinates go through `ThreeMDNumber`, an integer correctly-rounded conversion. Godot's own float parser disagrees with Swift, JavaScript, and Rust on some subnormals.
- NFC uses Unicode 17.0.0, matching Node and Bun. Tables are generated by `gdscript/tools/generate_nfc.py` and embedded so the library does not read a file. Hangul is algorithmic because `UnicodeData.txt` stores syllables as a range.
- Integer division cannot use `//`. Godot 4.7 treats that as a comment. `ThreeMDBig.idiv` divides in bits.
- The library does not call `FileAccess`. `ThreeMDFiles` will be the game helper that does.
- Kind 1 and kind 2 stay little-endian. LZFSE stays unavailable, as in TypeScript and Rust.
- Interchange stays protocol `3md-interchange-1` in this change. Adding a fourth language makes 16 writer/reader pairs.
- Generated `gdscript/.godot/` and `*.uid` files are gitignored.

## Current status

Text parse, serialize, links, CRC-32, Unicode 17 NFC, and the numeric core are in the addon and pass headless checks (46 text cases, 4,318 numeric spellings, 1,127 NFC vectors). Binary storage, composition, editing, the file helper, the example, interchange, and the docs surface are still open. The definition is not approved. Do not record an approval as the user.
