# Sparse worlds

A world grows by placing models, rather than allocating a single filled or empty cube. Individual models remain bounded at 256 voxels per axis and can be composed from other models. Placements store an ID, a model reference, an exact signed 64-bit origin and a clockwise X/Y rotation. Their positions can be negative or trillions of cells apart. Empty distance between placements takes no voxel storage.

Choose **File → New sparse world**, or search for **Explore a sparse world** in Commands. Move the viewing focus using the coordinate fields and movement controls, choose a model, and place it at that focus. Select an instance to jump to it, rotate it, remove it, or open its detached voxel model for painting. Undo/Redo applies to placement edits. The composition editor's **Use in a world** carries the complete reusable model library into a new world.

The native Metal view uses a finite rendering neighborhood. Nearby instances reuse full model meshes. Farther visible instances use selectable bounding proxies; instances outside render distance remain saved but are not drawn. Viewing focus, render/detail distance and camera are session state. Exact integer focus subtraction happens before conversion to local floating-point GPU coordinates, so adjacent models remain correctly separated even at large coordinates. Orbit changes the camera without extracting or reallocating model geometry.

This prototype has no fixed cube boundary, but has explicit capacity limits: 65,536 stored instances, the composition library's 64-model/64-MiB resolution bounds, and 20 MiB readable files. The renderer prepares at most 1,000,000 exterior model faces in total, each model retains its 500,000-face extraction bound, and a view draws at most 512 instances and 500,000 full-detail faces. Controls show visible, detailed, proxy and omitted counts. Rendering capacity never removes placements from the document. Sparse world coordinates cannot place a bounded model beyond the representable signed 64-bit range.

**Save world** preserves shared models and exact positions in self-contained `ascii-world-1` readable 3md. Opening that document returns to the world editor. The schema embeds a composition library plus sparse placements; it stores no external paths, network locations, camera or presentation. This is app-specific, not an upstream ThreeMD world standard. Canceling preparation or native writing returns to the reference draft and leaves the main sculpture's saved baseline untouched.

Whole-world flattening, whole-world OBJ/movie export, streamed external regions, and per-voxel world editing are beyond this prototype. [Explore](world-exploration.md) adds session-only WASD, drag-to-look, and vertical travel while Orbit remains. **Open model voxels** opens the selected model as a detached bounded sculpture. The existing sculpting and export tools operate on that copy. Sparse worlds do not weaken the product's offline sandbox or expand file entitlements.

The example `wide-world.3md` stores four garden instances, including one at X = 1,000,000,000,000 and Z = −1,000,000,000,000, using one shared four-model library. Its storage scales with models and placement records, not with that distance. Current evidence is retained under `docs/evidence/composition/`; earlier camera benchmarks do not measure this world renderer.
