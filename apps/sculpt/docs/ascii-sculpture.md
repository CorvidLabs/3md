## Current cube and ASCII editor

The current editor starts in Sculpt mode with translucent Cubes and the hollow orb. ASCII is another presentation of the same glyph volume. Style, camera, cube opacity, and the Paint interaction mode are session state. Readable 3md stores the title and bounded glyph layers in `ascii-sculpture-1`; native compact .3mdb stores that same title and volume without Markdown. A sculpture can have 1...256 columns, rows, and slices, and either file format is bounded at 20 MiB. Readable decoding has a private preparse limit of 100,000 physical lines to bound ThreeMD allocations; it does not add schema metadata. The original smaller documents remain valid.

Paint is an explicit mode. With Paint off, dragging orbits and a click selects a cell. With Paint on in Cubes view, Draw adds on an empty face neighbor or a visible empty square on the selected slice, Erase removes the clicked cube, and Fill changes the matching four-connected region on that cube's slice. Empty slice squares are pickable geometry, not occupied cubes. A face at the document boundary cannot add outside the volume. A live surface drag retains its starting scene, camera, opacity, empty-square inputs, and document generation; bitmap fallback retains its matching projected frame. A newly added cube therefore cannot push the next hit into another depth slice. The drag coalesces into one undo step; replacing the document ends the stroke.

## Native compact storage

The user's request to save 3md in binary confirms EXPORT-28. This prototype adds native `.3mdb` storage while preserving readable `.3md` in the existing ThreeMD schema. Compact is app-specific; no upstream ThreeMD binary standard is claimed. It stores the printable title and validated palette bytes in slice-major, row-major order. Camera, render style, cube opacity, and Paint state are omitted from both formats.

`SculptureBinaryCodec` writes a 60-byte little-endian version-1 header, title bytes, and one LZFSE stream of the raw voxel bytes. The header declares dimensions, title length, decoded voxel count, and compressed length. SHA256 covers the first 28 header bytes, title, and uncompressed voxels. Decode validates the 20 MiB file bound, 1...256 dimensions, exact lengths, complete stream with no trailing input, checksum, title, and glyph rules before returning a sculpture. It bounds decoded bytes by the dimension product, checks cancellation, and destroys initialized compression state on exit. Apple's Compression and CryptoKit are SDK dependencies; no package dependency, process, or network operation is added. The exact [native container layout and APIs](../specs/RookSculpture/RookSculpture.spec.md#native-compact-layout) are specified separately from readable 3md.

Header Save and Cmd-S default to compact storage. File → Save readable 3md… and Cmd-Shift-S explicitly choose readable text; Cmd-K offers both. Both prepare immutable title/volume snapshots away from the main actor, with cancellation and stale-request handling. A native save-panel success marks only the snapshot actually written, guarded against a replaced document; later edits remain dirty. Preparation/panel cancellation or failure does not mark the current document saved. Open detects either format from its content and leaves the current sculpture unchanged on rejection.

`RookTool sculpture inspect` can read either format. `sculpture apply` detects its input content and chooses output from a case-insensitive `.3md` or `.3mdb` extension; missing or unsupported extensions are refused. It keeps the 20 MiB sculpture and 256 KiB command-JSON bounds, validated atomic batches, and new-output-only publication. The repository gallery still supplies readable `.3md` alongside PNG, GIF, MP4, and OBJ: twenty-one examples and 105 artifacts. Compact storage does not redefine that five-format gallery.

The compact-storage lane passes 177 complete-suite tests and all seven pinned steps. Native compact/readable saves and reopen, cancellation, corrupt-file refusal, and optimized size/decode measurements are recorded in [compact storage evidence](evidence/compact-storage/verification-notes.md). [The format](compact-storage.md) remains distinct from readable ThreeMD. The 157-test solar-system receipts above precede this addition. No new lifecycle approval, review, finalization, merge authority, or human diff review is claimed.

## Layout

The header contains the document name and compact file, export, and command actions. Sculpt mode gives the 3D canvas most of the window beside a compact depth strip. Slice mode gives the character grid a large working area and places its tools in a scrollable contextual inspector. Cmd-1 and Cmd-2 switch modes; Cmd-K searches editor actions. Controls use the system font. Glyphs are monospaced. Chrome uses the existing palette: paper `#FAF9F6` / `#131619`, ink `#15181B` / `#F4F3EF`, accent `#0E6F66` / `#45D0BC`, secondary `#50555B` / `#A3A199`. The sculpture provides the visual emphasis. No purchased or generated resource is bundled. Menlo Bold is a system font used by the rasterizer.

There is no authored `.metal` shader. The live cube view uses SceneKit's Metal renderer and native scene picking; its exterior extraction is Swift. ASCII and CPU cube projection, rasterization, and picking remain available for bitmap display and export. If Metal is missing, the editor shows the CPU bitmap in an image view and says so.
