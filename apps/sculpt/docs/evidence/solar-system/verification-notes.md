# 256³ editing and solar-system verification

This work implements SCULPTURE-26 and SCULPTURE-27 under Leif's direct requests for a huge solar system and an editing volume of 256×256×256. These are Codex execution observations and delegated agent inspections, not independent human review or SpecSync lifecycle approval. Historical draft, halted, and archived records remain unchanged.

## Volume, rendering, and examples

Each document axis now supports 1–256 cells in the unchanged `ascii-sculpture-1` schema. The native File menu creates 16³, 32³, 64³, 128³, or 256³ volumes; Cmd-K also offers New 256-cubed volume. Slice zoom includes Fit, 2×, 4×, 8×, and 16× with two-axis scrolling. The slice list creates rows lazily, centers selection, and keeps three-digit selected numbers on one line. Appearance is still the only stored preference.

Canonical 256³ documents exceed the previous 1 MiB file budget; decoding now permits 20 MiB. Command JSON remains bounded at 256 KiB. A private 100,000-physical-line preflight bounds ThreeMD per-line allocations before parsing. Canceled decoding and ASCII projection return no partial document or picking frame. Private row and slice occupancy caches let sparse ASCII projections skip empty regions while preserving traversal and picking order.

Cube projection is bounded at 250,000 camera-visible quads, counting selected-slice ghost cells. A budget failure returns no partial quads or picking geometry, refuses rasterization, and explains the limit in the canvas with Slice and ASCII alternatives. OBJ independently retains its existing 250,000 exterior-face limit. These limits depend on surface complexity, rather than document dimension alone; a pathological disconnected volume can exceed them. Rendering remains worker-based and the product stays Swift, offline, sandboxed, and without development-tool imports, processes, network access, or bundled example resources.

The new Grand solar system is a native 256³ scene with 185,400 occupied cells, textured Sun and eight planets, Saturn and Uranus rings, moons, dotted orbit guides, asteroid belt, comet, and stars. Planet sizes and distances are artistically compressed. Continuous geometry is sampled at the new resolution rather than duplicating coarse blocks. All twenty earlier examples and their five-format artifacts were retained unchanged. The catalog now has 21 entries and 105 artifacts. The new canonical 3md is 16,854,166 bytes; its PNG, GIF, MP4, and OBJ accompany it in `Examples/` and `manifest.json` records the sizes.

The first solar export used zoom 1.05, which clipped the comet fan. Those five files were preserved outside the repository at `/private/tmp/sculpt-solar-first-framing-20261004`. Space gallery thumbnails and published fixtures now use zoom 0.9; the regenerated PNG was inspected and the full comet tail fits with margin. All eight planets remain recognizable. Some Jupiter moons overlap its disk in that view; the semantic tests establish their actual three-dimensional separation. These are agent visual observations, not human approval.

## Actual native app and file checks

The rebuilt app opened Grand solar system from its searchable Examples gallery and displayed it in the real Metal-backed canvas with 256³ dimensions and 185,400 occupied cells. Slice mode exposed the expanded zoom controls. At 16×, Right, Down, and Space painted cell 2,2 on slice 129, increasing occupancy to 185,401; Cmd-Z restored 185,400 and the clean document. A native save panel wrote the 16,854,166-byte 3md to a chosen temporary folder. Its bytes exactly match the canonical published example. Reopening that chosen file restored the title, dimensions, and occupied count.

Cmd-K search for 256 opened a new empty 256³ volume in Cubes with Paint enabled. Clicking the selected-slice plane added one cube at displayed cell 138,123,129, and Undo restored zero occupied cells. In Slice mode the slice scrollbar reached 256; with 16× zoom and both grid scrollbars at their maximum, clicking the final visible cell selected displayed X256, Y256, Z256 and painted the actual zero-based cell 255,255,255. Saving it produced a valid 256³ file with one occupied cell. The development CLI inspected it successfully, and raw final-grid inspection confirmed the last byte of the last row is `#`. File sizes and mesh counts are in [native-file-receipt.json](native-file-receipt.json).

The app is left open on Grand solar system in Cubes with Paint off and no unsaved changes. Temporary test documents remain outside the repository. The earlier 816-cell user torus backup remains untouched. The package retains its local ad-hoc signature and only the sandbox and user-selected read/write entitlements. This iteration does not claim native saves of the solar GIF, MP4, or OBJ; their actual generated files are decoded and validated by the complete artifact tests, including changing animation frames, timing, and OBJ geometry.
